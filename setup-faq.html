Setup FAQ

ECONS 431 Computational Economics

Start here when setup goes wrong. Most problems are one of the cases below. If yours isn’t, see Getting help at the bottom.

Your best diagnostic tool: from your repo folder, run

uv run python check_setup.py

Every line should start with [OK]. Each [!!] line says what to fix. Paste the whole output into any help request.

Codespaces

My repo is greyed out, or I don’t see “Create codespace”

Check that you accepted your repo invitation (step 2 of the Setup guide), and that you’re on your repo’s page: https://github.com/WSU-EconS431/ps-<your-username>. Use the green Code button there, then the Codespaces tab. If the repo is still greyed out, post on Discussions; it’s a course setting the instructor can fix.

How do I get back to my codespace?

Your repo’s page > Code > Codespaces tab > click the codespace listed there (it has a random two-word name). You can also see all of yours at github.com/codespaces. Reuse that one codespace all semester rather than creating new ones.

A notebook says “No module named numpy” (or asks me to select a kernel)

Click Select Kernel (or the kernel name) at the top right of the notebook, choose Python Environments, and pick the one in .venv. Then run the cells again.

I pressed Ctrl+W (or another shortcut) and my browser tab closed

Some shortcuts belong to the browser, not the editor. Reopen your codespace (see above); your files are still there, and the editor saves changes automatically.

Will I run out of codespace time?

Unlikely if you stop your codespace when you’re done. Your account includes about 60 hours a month, or 90 with GitHub student benefits. Check your usage under Settings > Billing on GitHub. To use less: close the tab when you’re done (it stops after 30 idle minutes), or stop it right away at github.com/codespaces (⋯ > Stop codespace). If you’re about to run out, set up your own computer as a backup.

My codespace disappeared

A codespace you don’t open for several weeks is deleted, along with anything not pushed to GitHub. Create a new one from your repo page; everything you pushed is still there. This is why every work session ends with commit and push.

“Pull” fails after I worked in a codespace and on my laptop

Your two copies changed in different ways. Always pull when you sit down and push when you get up. If a pull still fails, don’t force anything; post the message on Discussions.

Your own computer: installing

“uv is not recognized” (or “command not found”)

uv is installed, but your terminal started before it was. Close every terminal and Positron, reopen, and try again. If it still fails, rerun the uv install command from the setup guide.

I see two Pythons, or Python 3.14, or a Python I don’t recognize

That’s normal. Many computers already have one or more Pythons. The course uses its own Python 3.13, which uv sync downloads into your repo’s .venv folder. You don’t need to uninstall anything; you only need to select the .venv one (see below).

Your own computer: the Python environment

Positron shows a red ✕ and “A dedicated Python environment is available” (or offers to “Create Python environment”)

Don’t click the create button. It builds a different environment from the course one. Instead:

  1. Open your repo folder (File > Open Folder). It’s the folder that contains pyproject.toml.
  2. Open a terminal (Terminal > New Terminal) and run uv sync.
  3. Click the interpreter name at the top right of Positron and choose the Python from .venv.

A command gives “No module named uv” (or a Python SyntaxError)

You typed it into the Console, the panel with the >>> prompt, which runs Python code only. Commands such as uv, git, and cd go in the Terminal (Terminal > New Terminal), whose prompt shows your folder, like PS C:\Users\<you>\EconS431\ps-<your-username>>.

uv sync says it can’t find pyproject.toml

The terminal is in the wrong folder. Open your repo folder in Positron (File > Open Folder), then open a new terminal; it starts in the right place.

uv sync fails with “Failed to hardlink files” or “os error 396”

A sync or backup tool (OneDrive, Dropbox, and others) is blocking the file links uv uses to save disk space. Tell uv to copy instead:

uv sync --link-mode=copy

Current course repos already include this setting, so it should only affect older copies.

A notebook says “No module named numpy” (or pandas, scipy, …)

The notebook is running a different Python from the course one. Click the kernel name at the top right of the notebook and choose the Python from .venv (it’s labeled econs431). Then Restart the kernel and run the cells again. Positron usually remembers this choice for the folder.

check_setup.py says “Repo is outside a cloud-synced folder” is a problem

Your repo is inside OneDrive, Dropbox, iCloud, or Google Drive. Syncing the .venv folder (about 850 MB and 25,000 files) causes slowdowns and locked-file errors. Move the repo to a folder in your home folder that doesn’t sync, such as C:\Users\<you>\EconS431 (Windows) or /Users/<you>/EconS431 (Mac).

Watch out: on many laptops, Desktop and Documents are synced (OneDrive on Windows, iCloud on Mac) even if you never set that up. If the path contains OneDrive, Dropbox, iCloud, or Mobile Documents, it syncs.

My .venv folder is huge, and Windows won’t let me delete or move it

Its size is normal: it holds compiled scientific libraries. It’s never uploaded to GitHub, and uv sync rebuilds it in a minute, so deleting it is always safe.

Windows refuses because a program still has its files open:

  1. Quit Positron completely, including from the system tray.
  2. In Task Manager, end any leftover python.exe processes.
  3. If the folder is in OneDrive or Dropbox, pause syncing.
  4. Delete it. If Windows still refuses, restart the computer and delete it before opening anything else.

Your own computer: GitHub and Git

The browser asks me to “Authorize Visual-Studio-Code”

That’s expected. Positron is built on VS Code and uses VS Code’s GitHub sign-in. Check that the address starts with https://github.com/, then authorize.

GitHub says I’m connected, but Positron says “failed to sign in to GitHub”

The browser couldn’t hand the sign-in back to Positron. You don’t need that sign-in; let Git sign in on its own:

  1. In Positron, open Settings (Ctrl+, or Cmd+,), search for github.gitAuthentication, uncheck it, and restart Positron.
  2. When you clone, choose Git: Clone and paste your repo’s URL rather than choosing “Clone from GitHub”.
  3. The first clone or push opens a sign-in window. Choose the browser option.

How do I know Git can sign in to GitHub?

Windows: run

git config --show-origin --get-all credential.helper

You should see manager (from C:/Program Files/Git/etc/gitconfig). If you see nothing, run git config --global credential.helper manager.

Mac: install the GitHub CLI from cli.github.com, then run these two commands and choose the web-browser login when asked:

gh auth login
gh auth setup-git

check_setup.py says “Repo is connected to GitHub” is a problem

You’re working in a copy of the files rather than a clone of your GitHub repo. Clone your repo (Git: Clone, paste https://github.com/WSU-EconS431/ps-<your-username>.git), then run uv sync in the new folder. Copy any work you want to keep into the clone.

I get “Repository not found” (or 404) for my repo

You haven’t accepted the invitation yet. Open the email from GitHub, or go to https://github.com/WSU-EconS431/ps-<your-username>/invitations while signed in.

check_setup.py says git user.name or git user.email isn’t set

Run these once, with your own name and the email on your GitHub account:

git config --global user.name "First Last"
git config --global user.email "you@example.com"

“Commit operation was cancelled due to empty commit message”

(This happens in Codespaces too.) Every commit needs a short message saying what it contains. Type one in the box above Commit in Source Control (for example, “PS02 Q1-Q3 done”), then click Commit. If Positron opens a COMMIT_EDITMSG tab instead, type the message on its first line, then save and close the tab.

Notebooks

How do I tick the boxes in the PS01 checklist?

Double-click the checklist cell to edit it, change [ ] to [x], then press Shift+Enter.

The kernel is named “econs431” (or “.venv”). Is that right?

Yes. Positron labels the course environment econs431; Codespaces shows it as the Python in .venv. Either way it’s the course environment in your repo’s .venv folder.

Still stuck after 30 minutes?

If you’re setting up your own computer, switch to Codespaces so you’re not blocked: on your repo’s GitHub page, click Code > Codespaces > Create codespace on main. Everything is preinstalled there. Then post your problem (see below) so we can fix your laptop setup later. If Codespaces itself is the problem, post right away.

Getting help

Post on Discussions

Include all four of these, so someone can help on the first reply:

  1. Where you’re working: Codespaces, or your own Windows or Mac computer.
  2. The setup step you were on.
  3. The exact error text, copied as text (not a screenshot).
  4. The full output of uv run python check_setup.py, if you can run it.

Answering a classmate’s setup question counts toward participation.

Ask an AI assistant (with the right context first)

Generic AI advice often conflicts with this course’s setup. It may tell you to pip install numpy, install Anaconda, or create a new environment, and those make things worse here. Paste this context first, then your problem. Microsoft 365 Copilot Chat (sign in with your WSU account) is free and works well for this.

I'm setting up a Python course environment. The setup is fixed and I must not
change it:
- Editor: GitHub Codespaces (VS Code in the browser), or Positron on my own
  computer (built on VS Code).
- Python environment: managed by uv. My repo has pyproject.toml, uv.lock and
  .python-version (Python 3.13). The environment is built with `uv sync` into a
  .venv folder in the repo.
- Code lives in a private GitHub repo. In Codespaces, Git signs in
  automatically; on my own computer, Git signs in with Git Credential Manager
  (Windows) or the GitHub CLI (Mac).
- The repo checker is `uv run python check_setup.py`; [!!] lines are problems.

Rules for your answer:
- Do NOT suggest pip install, conda/Anaconda, a new virtual environment,
  changing pyproject.toml or uv.lock, or a different Python version.
- Fixes should use: uv sync, choosing the .venv interpreter or kernel in
  Positron, moving the repo out of a cloud-synced folder, or Git/GitHub
  settings.
- Give me ONE step at a time, tell me what I should see if it worked, and wait
  for my result before the next step.

Where I'm working: [Codespaces, or my own Windows/Mac computer]
What I was doing: [setup step or command]
Exact error text: [paste]
check_setup.py output: [paste, if available]

Two more prompts that help:

  • Before running a Git command you’re unsure about: “Before I run [command], explain in plain language what it will do, and whether it can lose any of my work. Don’t suggest alternatives unless it’s risky.”
  • When an error message makes no sense: “Explain this error in plain language for a beginner: what it means, the most likely cause, and the first thing to check. Error: [paste]”

Setup guide

You’ll do your coding in GitHub Codespaces: the course’s Python setup, running on GitHub’s computers and shown in your web browser. There’s nothing to install, and it works the same on any laptop, a Chromebook, or a campus lab computer. Do steps 1–5 before the second class session. If you get stuck, see the Setup FAQ.

Prefer a desktop editor or working offline? You can also work on your own computer. That’s optional, and you can add it any time.

Before you start: an internet connection, a current web browser (Chrome, Edge, Firefox, or Safari), and your phone for GitHub’s sign-in codes.

One-time setup

  1. GitHub: the website that stores your course work online. Each student gets a private repository (“repo”) there, a folder only you and the instructor can see. New problem sets arrive in it. To hand in work, you use Git to save it to your repo, then submit the link to it in Canvas.

    • Sign up at github.com with any username (it doesn’t need to be your real name), and add your WSU email to the account.
    • Apply for GitHub Education student benefits at education.github.com. Approval can take a few days; it gives you free GitHub Copilot and free Codespaces hours.
    • GitHub will ask you to set up two-factor sign-in. Keep that phone or app handy: you’ll need a code when you sign in on a lab computer.
    • Enter your GitHub username in the Canvas “GitHub username” survey, so your course repo can be created.

  2. Accept your repo invitation from the email GitHub sends you, or at https://github.com/WSU-EconS431/ps-<your-username>/invitations.

  3. Create your codespace. On your repo’s page (https://github.com/WSU-EconS431/ps-<your-username>), click the green Code button, choose the Codespaces tab, and click Create codespace on main.

    • The first time takes a few minutes while it installs Python and the course packages. Then an editor opens in your browser. It’s VS Code, the program Positron is built on.
    • If it offers to turn on GitHub Copilot or AI code completions, skip it for now. AI autocomplete stays off through Week 5 (see Policies).

  4. Check it. Open a terminal: click the ☰ menu at the top left, then Terminal > New Terminal (or press Ctrl+`). Run:

    uv run python check_setup.py

    Every line should start with [OK].

  5. Do PS01. In the file list on the left, open ps01/ps01.ipynb. If the notebook asks you to Select Kernel (top right), choose Python Environments, then the one in .venv. Complete it, then:

    • In Source Control (the branching icon on the left), type a short message such as “PS01 done” in the box and click Commit. Every commit needs a message.
    • Click Sync Changes to push it to GitHub.
    • On your repo’s GitHub page, open the commit, copy its URL, and paste it into the PS01 assignment in Canvas.

Each time you work

  • Open your codespace: your repo’s page > Code > Codespaces tab > click the codespace that’s already there. Reuse it; don’t create a new one each time.
  • Start by pulling: in Source Control, click Sync Changes (or ⋯ > Pull) so you have any new problem sets.
  • Before you leave: commit and push. Your work is only safe once it’s on GitHub. A codespace you stop using for a few weeks is deleted, and anything not pushed goes with it.
  • Then close the tab. The codespace stops by itself after 30 idle minutes. To stop it right away, go to github.com/codespaces, click ⋯ next to it, and choose Stop codespace.
  • On a lab or shared computer, sign out of GitHub when you’re done.

Your monthly allowance: your GitHub account includes about 60 hours of codespace time a month, or 90 once your student benefits are approved. That’s plenty for this course if you stop your codespace when you’re done. You can see your usage under Settings > Billing on GitHub.

Every problem set

  1. Pull (Source Control > Sync Changes). The new psNN/ folder appears.
  2. Work in psNN/psNN.ipynb, and commit whenever something works.
  3. Restart & Run All. If it doesn’t run from top to bottom, it isn’t finished.
  4. Fill in the AI usage note at the bottom.
  5. Commit, push (Sync Changes), copy the commit URL from GitHub, and paste it into Canvas before the deadline.

Rules of the road

  • Your repo is private. Never make it public or share it, even after the course, unless an assignment says it may be shared.
  • Use relative paths (data/prices.csv), never full paths like C:\Users\... or /workspaces/.... Your code must run on the instructor’s machine.
  • Don’t commit .venv/ or big data files. GitHub rejects files over 100 MB, and your repo’s .gitignore handles the common cases.
  • Don’t change pyproject.toml or uv.lock. If you think you need another package, ask on Discussions.
  • Asking for help: see Getting help.
